<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user message -> Jinja2 prompt render | user-supplied lead text near system prompt |
| BusinessProfile (in-code) -> Jinja2 | template variables come from Pydantic-validated source |
| env var (API keys) -> LiteLLM Router | secret material loaded at import time |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | Prompt injection via lead message | mitigate | Lead text NEVER interpolated into system prompt — only into user-role messages; system prompt is rendered ONCE from BusinessProfile only (RESEARCH.md Security Domain) |
| T-03-02 | Repudiation | Missing NPC 2024-04 AI disclosure | mitigate | base.j2 contains hardcoded disclosure phrase "ako ay AI assistant"; tests/test_models.py asserts the phrase is present in every rendered template |
| T-03-03 | Information Disclosure | API keys in logs | mitigate | `.env.example` documents `LITELLM_LOG=ERROR`; Router never prints `litellm_params` content (verified via test on `repr(router)`) |
| T-03-04 | Tampering | Jinja2 SSTI via BusinessProfile fields | mitigate | BusinessProfile is internally defined in Phase 1 (DEMO_PROFILES is a hardcoded dict); Pydantic validates types before render; `StrictUndefined` catches missing fields |
| T-03-05 | Denial of Service | Groq 429 cascade | mitigate | `rpm:30, tpm:6000` on Groq deployment + fallback to Gemini -> Mistral (test_llm_router.py asserts both) |
</threat_model>
