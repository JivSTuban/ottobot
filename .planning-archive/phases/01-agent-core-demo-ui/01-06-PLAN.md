<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user keyboard -> WebSocket send | untrusted text crosses to backend |
| Vite dev server -> backend WebSocket | client-supplied threadId |
| public/ image bytes -> rendered DOM | generated PNGs ship to client |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Tampering | User-controlled threadId | mitigate | App.tsx uses `crypto.randomUUID()` only (uuid4); backend rejects non-uuid4 (Plan 05 validate_thread_id, close code 1008) |
| T-06-02 | Tampering | XSS via assistant token content | mitigate | React renders text via JSX `{content}` only — no `dangerouslySetInnerHTML`; default escaping applies |
| T-06-03 | Information Disclosure | WS URL exposes thread to anyone with the link | accept | Phase 1 demo is single-tenant; multi-tenant auth deferred to Phase 5 |
| T-06-04 | Denial of Service | Unbounded message list causes browser memory bloat | accept | Demo conversations capped at ~20 turns per AI-SPEC; not a real risk in Phase 1 |
| T-06-05 | Spoofing | Persona avatar tampering at runtime | mitigate | Images served from same-origin `public/`; CSP not required in Phase 1 demo |
</threat_model>
